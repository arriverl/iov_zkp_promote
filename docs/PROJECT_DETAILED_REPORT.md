# ZKP-PQC-PLS 项目详细技术报告

## 1. 项目概述

本项目面向车联网（IoV/V2X）身份认证，构建了一个融合 **零知识证明（ZKP）**、**后量子密码（PQC）** 和 **物理层安全（PLS）** 的多因子认证系统。目标是在满足实时性约束的前提下，提升认证系统在抗量子、隐私保护与防远程冒充方面的综合安全能力。

系统代码已具备可复现实验能力，包含主对比、攻击仿真、消融分析、参数敏感性与规模评估五组实验。

---

## 2. 采用的算法方案

### 2.1 PQC：格基签名（Dilithium/ML-DSA）

- **实现位置**：`src/pqc/lattice_signing.py`
- **核心接口**：
  - `keygen()`：生成公私钥 `(pk, sk)`
  - `sign(message, sk)`：对认证消息签名
  - `verify(message, signature, pk)`：验签
- **作用**：
  - 提供消息完整性和身份真实性
  - 提前适配量子威胁场景（替代传统 ECC 的长期风险）

本项目默认采用 `security_level=2`，在安全与性能之间做平衡；敏感性实验中也测试了 `level=3`。

### 2.2 ZKP：Sigma + Fiat–Shamir 非交互证明

- **实现位置**：`src/zkp/sigma_proof.py`
- **核心流程**：
  1. `commit`：基于私密证据生成承诺
  2. `challenge`：用 Fiat–Shamir 从公共输入与消息派生挑战
  3. `response`：输出响应，形成非交互证明
  4. 验证端重算挑战并校验证明一致性
- **作用**：
  - 在不泄露敏感身份细节前提下完成“拥有合法凭证”的证明
  - 为匿名认证与最小信息披露提供基础

### 2.3 PLS：基于 CSI 的物理层指纹认证

- **实现位置**：`src/pls/csi_fingerprint.py`
- **算法特征**：
  - 使用 Rayleigh 多径模型模拟 CSI 指纹
  - 计算皮尔逊相关系数作为匹配度
  - 与阈值比较决定是否通过第二因子认证
- **作用**：
  - 抵抗“证书被盗但攻击者不在同一物理信道环境”的远程冒充攻击

### 2.4 会话绑定与防重放机制

- **实现位置**：
  - `src/protocol/iov_auth_frame.py`
  - `src/protocol/fusion_protocol.py`
- **关键机制**：
  - 使用 `IoVAuthFrame` 绑定 `RSU ID + timestamp + nonce + policy_flags`
  - RSU 侧引入 Replay Guard（短时窗口内消息指纹去重）
- **作用**：
  - 明确上下文绑定，降低跨会话重放风险
  - 在攻击实验中将 replay 成功率从可成功压到 0

## 3. 设计流程（端到端）

### 3.1 OBU 侧（车辆端）

1. 生成/加载 PQC 密钥对  
2. 构造 `IoVAuthFrame`（RSU 标识、时间戳、随机 nonce）  
3. 用会话帧字节作为认证消息：
   - 生成 ZKP 证明
   - 生成 PQC 签名
4. 提取并上报 CSI 指纹
5. 发送认证请求到 RSU

### 3.2 RSU 侧（路侧单元）

1. 先做 Replay Guard（窗口内去重）  
2. 验证 ZKP  
3. 验证 PQC 签名  
4. 对比上报 CSI 与本地测量 CSI  
5. 三项均通过才认证成功，建立后续会话

## 4. 改善了哪些板块

相对早期原型/基线方案，本项目新增并改善了以下能力：

1. **安全架构层面**
   - 从单一密码认证扩展为跨层融合（PQC + ZKP + PLS）
   - 形成“数字凭证 + 物理在场性”联合认证

2. **协议流程层面**
   - 引入 `IoVAuthFrame` 做会话上下文绑定
   - 增加 RSU 端防重放窗口检测

3. **实验体系层面**
   - 新增 `src/attacks/`：攻击仿真
   - 新增 `src/ablation/`：模块消融
   - 新增 `configs/`：多配置策略
   - 新增 `scripts/run_all.py` 与 `scripts/plot_results.py`：一键复现与出图

4. **研究可复现性**
   - 输出统一 CSV 与图表
   - 可直接支撑论文实验章节和答辩展示

## 5. 对比数据与含义说明（基于当前 `results/`）

### 5.1 主对比（`group1_main_comparison.csv`）

- Baseline（Yang 模拟）：
  - 延迟约 `0.55 ms`
  - 开销 `256 B`
- ECDH+AES 改进：
  - 延迟约 `2.91 ms`
  - 开销 `512 B`
- 创新方案（ZKP-PQC-PLS）：
  - 延迟约 `4.87 ms`
  - 开销 `4414 B`

**说明**：
- 创新方案比基线更慢、开销更大，这是引入抗量子签名与多因子防护的必然代价；
- 但延迟仍远低于 IoV 常用实时阈值（50ms），具备可部署性；
- 该对比体现的是“安全能力提升 vs 成本增加”的工程权衡。

### 5.2 消融实验（`group2_ablation.csv`）

当前 benign 流量下，不同变体认证成功率均为 `1.0`，例如：
- `full`
- `no_zkp`
- `no_pls`
- `no_session_binding`
- `pqc_only`

**说明**：
- 消融在“正常流量”下主要验证流程可用性与模块可插拔；
- 它不能单独说明安全优劣，需结合攻击实验一起解释模块价值。

### 5.3 攻击实验（`group3_attacks.csv`）

- `replay`：成功率 `0.0`
- `certificate_theft_impersonation`：成功率 `0.05`
- `remote_relay`：成功率 `0.0`
- `message_tampering_mitm`：成功率 `0.0`

**说明**：
- Replay Guard 有效，重放攻击已被拦截；
- 篡改与远程中继防护效果明显；
- 证书窃取仍有少量误通过（5%），后续可通过多窗口 CSI 一致性和动态阈值进一步压低。

### 5.4 参数敏感性（`group4_sensitivity.csv`）

主要观察：
- `pqc_level=2`：延迟约 `4.7~5.2 ms`，通信约 `4025~4409 B`
- `pqc_level=3`：延迟约 `7.4~8.0 ms`，通信约 `5538~5922 B`
- `csi_dim` 增大时通信开销同步上升

**说明**：
- PQC 安全级别是性能和开销的主要影响因素；
- 默认 level2 适合工程平衡，level3 适合更高安全需求场景。

### 5.5 规模实验（`group5_scalability.csv`）

- 20 车辆：吞吐约 `44.48 auth/s`
- 50 车辆：吞吐约 `35.63 auth/s`
- 100 车辆：吞吐约 `36.24 auth/s`
- 成功率均为 `1.0`

**说明**：
- 在 100 车辆规模下仍保持稳定认证吞吐；
- 系统具备原型级并发处理能力，可继续向更大规模优化。

---

## 6. 结论

1. 本项目已实现可运行、可复现、可扩展的 IoV 多因子认证研究系统。  
2. 相比传统基线方案，系统在抗攻击和综合安全能力方面有明显提升。  
3. 实验表明系统延迟满足实时性约束，但通信开销较高，符合“以性能换安全”的设计取向。  
4. 通过新增 replay 防护，已修复关键安全短板；后续重点是继续降低证书窃取冒充场景的残余成功率。

---

## 7. 后续优化建议

- PLS 改进：多窗口 CSI 一致性判定 + 动态阈值（按噪声/SNR）  
- PQC 工程化：替换为高性能 OQS/C 后端  
- ZKP 深化：从当前骨架升级到电路化 zk-SNARK 流程  
- 攻击评估扩展：加入轨迹关联攻击、跨 RSU 切换认证实验
